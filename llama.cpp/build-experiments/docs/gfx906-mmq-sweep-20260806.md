# gfx906 MMQ Tile Sweep: 2026-08-06

## Purpose

Tune the prompt-processing `mul_mat_q` kernels for MI50 after establishing
`-mllvm -amdgpu-sched-strategy=max-ilp` as the ROCm 7.14 compiler baseline.
The upstream code routes gfx906 through `mmq-config-rdna2.cuh`; this experiment
adds a gfx906-specific configuration without changing kernel math.

## Controlled configuration

- llama.cpp: `360e1349f0009c5ad99d21e3c4546b707addc68a`
- ROCm 7.14, LLVM 23, target `gfx906`
- Compiler flag: `-mllvm -amdgpu-sched-strategy=max-ilp`
- Device: one MI50, `ROCm0`
- `--n-prompt 2048 --ubatch-size 2048 --batch-size 2048 --n-gen 256`
- `--n-depth 0 --split-mode layer --flash-attn on`
- Models: Qwen3.5-9B Q8_0 and Gemma-4-26B A4B Q4_K_L

## Variants

All overrides apply only to J=64 and keep 256 threads, occupancy target 2,
K=256, and `stream_k=false`.

| Variant | Q8_0 I | Q4_K I | Q5_K I | Q6_K I |
| --- | ---: | ---: | ---: | ---: |
| `gfx906-i128` control | 128 | 128 | 128 | 128 |
| `gfx906-i96` | 96 | 96 | 96 | 96 |
| `gfx906-i64` | 64 | 64 | 64 | 64 |
| `gfx906-q8-i64` | 64 | 128 | 128 | 128 |
| `gfx906-mixed-i64` | 64 | 128 | 64 | 64 |

## End-to-end results

Values are tokens per second.

| Variant | Qwen PP | Qwen TG | Gemma PP | Gemma TG |
| --- | ---: | ---: | ---: | ---: |
| Previous 7.14 `maxilp` | 729.72 | 60.56 | 1310.77 | 86.52 |
| `gfx906-i128` control | 729.78 | 60.82 | 1307.16 | 86.47 |
| `gfx906-i96` | crash | not run | not run | not run |
| `gfx906-i64` | 733.23 | 60.79 | 1215.75 | 86.58 |
| `gfx906-q8-i64` | 734.46 | 60.76 | 1309.98 | 86.48 |
| `gfx906-mixed-i64` | **735.41** | 60.75 | **1362.88** | 86.36 |

The final mixed configuration improves Qwen PP by `0.8%` and Gemma PP by
`4.0%` over the previous `maxilp` result. TG is effectively unchanged: Qwen
is `+0.3%` and Gemma is `-0.2%`.

`gfx906-i96` compiled successfully but the first Qwen benchmark failed with
`HSA_STATUS_ERROR_MEMORY_APERTURE_VIOLATION`. The MMQ indexing therefore has
a hidden requirement not expressed by the existing `I % 32 == 0` assertion.
The empty Qwen JSONL and build artifacts are preserved; no performance result
is inferred from this failure.

## Kernel attribution

rocprof totals for the J=64 non-fallback kernels:

| Type | Format | I=128 control | Final mixed | Change |
| ---: | --- | ---: | ---: | ---: |
| 8 | Q8_0, Qwen | 13.752 s | 13.653 s | `-0.7%` |
| 8 | Q8_0, Gemma | 1.468 s | 1.431 s | `-2.5%` |
| 12 | Q4_K | 1.954 s | 1.994 s | `+2.0%` |
| 13 | Q5_K | 1.105 s | 0.934 s | `-15.5%` |
| 14 | Q6_K | 0.631 s | 0.411 s | `-34.9%` |

The all-I=64 variant showed why the override must be format-specific. Q4_K
rose from 1.954 s to 2.985 s (`+52.8%`), overwhelming the Q8_0, Q5_K, and
Q6_K gains and reducing Gemma PP by 7.0%.

## Resource attribution

HSACO metadata for J=64, fallback=false:

| Format | I=128 VGPR / scratch | I=64 VGPR / scratch |
| --- | ---: | ---: |
| Q8_0 | 119 / 0 B | 71 / 0 B |
| Q4_K | 128 / 64 B | 128 / 52 B |
| Q5_K | 128 / 80 B | 128 / 68 B |
| Q6_K | 128 / 56 B | 126 / 0 B |

Reducing I halves the accumulator array from 32 to 16 floats per thread and
roughly halves the X tile in LDS. Q8_0 substantially reduces VGPR use, while
Q6_K eliminates scratch entirely. Q4_K remains capped at 128 VGPR and loses
enough tile reuse that its small scratch reduction does not help performance.

## Production change

`build-context/patch/gfx906-mmq-i64.patch` adds `mmq-config-gfx906.cuh` and routes
Vega20/gfx906 host and device dispatch to it. The final configuration uses
I=64 for Q8_0, Q5_K, and Q6_K, and retains I=128 for Q4_K. All unsupported
types and J values fall back to the existing RDNA2 configuration.

`build-image.Dockerfile` applies this patch unconditionally after checking out
llama.cpp. This repository targets MI50 only, so no portability switch is
maintained.
