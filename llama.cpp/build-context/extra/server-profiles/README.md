# Server profiles

`build-presets-ini.py` combines YAML and JSON profiles into a llama.cpp router
server presets INI file. It supports nested option names, lists, tensor placement
groups, and JSON chat template arguments.

## Container usage

Profile generation is optional. The container entrypoint attempts it before
running `tools.sh`, but does not automatically enable the generated presets in
llama.cpp.

| Environment variable            | Purpose                                                                  | Default                                                              |
| ------------------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| `M36_LLAMA_MODELS_PRESETS_DIR`  | Directory searched recursively for profiles                              | `./server-profiles`                                                  |
| `M36_LLAMA_MODELS_PRESETS_FILE` | Generated INI destination                                                | `LLAMA_ARG_MODELS_PRESET`, otherwise `./server-profiles/presets.ini` |
| `LLAMA_ARG_MODELS_PRESET`       | Tells llama.cpp which INI to use; also a fallback generation destination | Not automatically exported                                           |

Relative paths are resolved from the container's working directory, `/app` by
default. Mount your profiles in a separate directory so that the bundled
generator at `/app/server-profiles/build-presets-ini.py` stays accessible.

For example, with your image tag in `LLAMACPP_IMAGE`:

```bash
docker run --rm \
  --device /dev/kfd --device /dev/dri \
  -p 8080:8080 \
  -v "$PWD/profiles:/config/profiles:ro" \
  -v "$PWD/models:/models:ro" \
  -e M36_LLAMA_MODELS_PRESETS_DIR=/config/profiles \
  -e LLAMA_ARG_MODELS_PRESET=/app/server-profiles/presets.ini \
  "$LLAMACPP_IMAGE" --server --host 0.0.0.0
```

Use container paths in profile options, for example `model: /models/model.gguf`.
The generated INI destination must be writable; the source directory can be
read-only.

On successful generation, the entrypoint prints the INI and starts the requested
tool. If generation fails (including when no profiles are found), it prints the
error and still starts the tool. A previously generated INI is not replaced when
parsing or rendering fails, so it can remain in use. This behavior keeps profile
generation optional for users running the image's other workflows.

You can also pass `--models-preset PATH` to the server explicitly. The generator
does not inspect CLI arguments: set `M36_LLAMA_MODELS_PRESETS_FILE` as well if
you want to change where it writes the file. This variable only controls
generation; use `LLAMA_ARG_MODELS_PRESET` or `--models-preset` to select that
file in llama.cpp.

## Profile format

Every document maps preset names to option mappings. Files ending in `.yaml`,
`.yml`, or `.json` are discovered recursively. YAML files can contain multiple
documents separated by `---`. Files ending in `.sample` are ignored: copy a
sample and remove that suffix to activate it.

```yaml
"*":
  jinja: true
  cache-ram: 8192

my-model:
  enabled: true
  model: /models/model.gguf
  load-on-startup: false
  ctx-size: 32768
  device: [ROCm0, ROCm1]
  tensor-split: [1, 1]
  reasoning:
    preserve: false
  chat-template-kwargs:
    enable_thinking: false
```

Produces:

```ini
# Generated by build-presets-ini.py 0.1.0.
# This file will be overwritten by build-presets-ini.py on the next successful generation.
# Edit the source YAML/JSON profiles instead of this file.

version = 1

[*]
jinja = true
cache-ram = 8192

[my-model]
model = /models/model.gguf
load-on-startup = false
ctx-size = 32768
device = ROCm0,ROCm1
tensor-split = 1,1
reasoning-preserve = false
chat-template-kwargs = {"enable_thinking":false}
```

- `"*"` supplies shared defaults to llama.cpp and is emitted first. Quote it in
  YAML. Other sections are sorted by name.
- `enabled` defaults to `true`. It must be a boolean; `false` skips the entire
  preset. This generator-only option is omitted from the INI. Use
  `load-on-startup` to control loading without removing the preset.
- Enabled preset names must be unique across files and documents. Profiles with
  the same name are not merged; put shared defaults in a single `"*"` section.
- Nested mappings become dash-separated keys: `spec: {draft: {n-max: 3}}`
  becomes `spec-draft-n-max = 3`. Avoid defining the same flattened key twice.
- Ordinary lists of scalars become comma-separated values. Use a string when an
  option expects another format or separator.
- Booleans become `true` / `false`, numbers become text, and `null` becomes an
  empty value. Strings are copied as-is; no environment or template expansion
  is performed. Quote YAML strings such as `"on"` and `"off"` to keep PyYAML from
  interpreting them as booleans.

The generator converts structure, not llama.cpp's option schema. Option names,
values, devices, and model paths must be valid for the llama.cpp build you run.

### Tensor placement

`override-tensor` accepts either a ready-made string or a list of groups. Each
group must contain exactly `tensors` (a list of patterns) and `target`:

```yaml
my-model:
  override-tensor:
    - tensors:
        - 'blk\.0\.ffn_(up|down)_exps\.weight'
        - 'blk\.1\.ffn_(up|down)_exps\.weight'
      target: CPU
```

Produces:

```ini
override-tensor = (blk\.0\.ffn_(up|down)_exps\.weight|blk\.1\.ffn_(up|down)_exps\.weight)=CPU
```

Patterns within a group are joined with `|` inside parentheses; groups are joined
with commas. Regex patterns are preserved, not escaped by the generator.

### Chat template arguments

`chat-template-kwargs` accepts a mapping, serialized as compact JSON, or a string
containing ready-made JSON. Nested values inside this mapping remain JSON rather
than becoming dash-separated INI keys.

## INI limitations

The current llama.cpp presets parser treats `#` and `;` as comment delimiters,
even inside quotes or without a preceding space. It does not provide general
backslash escaping or multiline values. The generator does not escape or reject
these cases, so successful generation does not guarantee that llama.cpp will
read every value as intended.

- A value such as `samplers: "top_k;top_p;temperature"` is written verbatim, but
  llama.cpp reads only `top_k` from the INI.
- Literal newlines in values (for example, YAML `|` blocks) can produce invalid
  INI. For a multiline Jinja template, use `chat-template-file` with a path to a
  separate template file.
- For `chat-template-kwargs`, JSON escapes can preserve these characters. Supply
  ready-made JSON in a **single-quoted YAML string** to preserve the backslashes:

  ```yaml
  my-model:
    chat-template-kwargs: '{"prompt":"\u0023 title\u003b text\nnext line"}'
  ```

  The JSON parser later restores `#`, `;`, and the newline. Mapping-form kwargs
  do not automatically escape `#` or `;`. JSON escapes are not a general solution
  for other INI options.

Preset names and option keys are also written verbatim. Use names and keys that
are valid in llama.cpp's INI format.

## Standalone usage

Requires Python 3.10+ and PyYAML. Run from this directory:

```bash
python3 build-presets-ini.py --source-dir ./profiles --output ./presets.ini
```

To preview the generated file on stdout:

```bash
python3 build-presets-ini.py --source-dir ./profiles --output -
```

The generator creates missing destination directories and replaces the output
file atomically after rendering. Running it directly returns a nonzero exit
status on errors; the container entrypoint intentionally continues after a
generation error.

See [global.json.sample](global.json.sample) and
[deepseek-v4-flash.yaml.sample](deepseek-v4-flash.yaml.sample) for more examples.
Adjust the model, GPU layout, and memory settings for your system before use.
